# Financial Manager AI V2 — Release Candidate

Candidate: **v2.0.0**  
Decision: **REMEDIATION REQUIRED — NOT READY FOR RELEASE**  
Date: 2026-11-23

## Implemented scope and architecture

The candidate contains exactly four generic executable domains (9 Sales, 6
Payable, 6 Receivable, 6 Cash operations), two Sales/Profit anomaly screens,
safe onboarding/current readiness, deterministic Manager/Core/Anomaly execution,
Application Layer, local FastAPI `/api/v1`, Web Financial Workspace, compatible
CLI workflows and optional loopback conversation. Forecasting/RAG/fraud/arbitrary
query/auth/SaaS/cloud/ERP/banking/PostgreSQL/mobile remain deferred.

## Repository hygiene

Tracked release content excludes raw/processed/onboarding user data, SQLite,
`.venv`, `node_modules`, `.next`, Playwright/coverage output, `.env.local`, local
LLM data, IDE/Codex state and secrets. `next-env.d.ts` was corrected to follow
Next 16 policy: generated by `next typegen`, ignored and not tracked.

Local `AGENTS.md` and `web/AGENTS.md` are untracked user guidance and must remain
excluded from the release unless the user separately decides otherwise;
`.agents/` and `skills-lock.json` are ignored agent state. The pre-existing user
change in `CONTEXT.md` is preserved and must be reviewed separately when staging.

## Current remediation status

A later tasteskill audit confirmed three P0 release blockers, eight P1 risks and
five P2 craft findings. Phase 5 remediated and functionally validated all 16; see
[`v2_phase5_release_remediation.md`](v2_phase5_release_remediation.md). The final
automated gate returned `GATE: ERROR` because its isolated checker could not reach
the rendered application. This candidate is therefore still not a final release.
The findings below describe the earlier functional gate and remain historical
evidence rather than the current release decision.

## Findings at the initial candidate gate

- BLOCKER: none.
- HIGH: none.
- MEDIUM: original HTTP upload filename was replaced by the random staging name;
  fixed and regression-tested. Generated `next-env.d.ts` dirtied the tree after
  build; fixed by the documented Next 16 generation/ignore policy.
- LOW: explicit catalog representations exist in several layers; frozen enums,
  OpenAPI and exact catalog tests mitigate synchronization risk. Browser E2E logs
  contain benign `sys.prefix` and color warnings. No live local LLM was available;
  provider-unavailable behavior passed and model use is optional.
- OBSERVATION: legacy private data remains custodian-provided and is not
  redistributable from Git. Runtime is local single-user and not publicly hosted.

## Limitations

Offline-capable means after installation/provisioning and permits loopback.
Installation/update may need Internet. The host could not enable loopback inside
the isolated network namespace, so no-route backend and proxy-blocked real-browser
tests were complementary. This does not leave a mandatory external dependency.

## Recommendation

Do not release or tag `v2.0.0` until a fresh authorized tasteskill audit can run
its copy, consistency and checker modules and returns PASS/OPEN without a release
blocker. Functional/security gates and all P0/P1/P2 reconciliation otherwise pass.
Do not start V2.x/V3 or Phase 6 as part of this remediation.
